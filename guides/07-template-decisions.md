# Template decisions

Decisions about the template itself, from audits, one line each, newest last; cite as "guide 07 finding 2". Open work: the [issues labelled `template`](https://github.com/euginevd/sdlc-template/issues?q=is%3Aissue+is%3Aopen+label%3Atemplate). A project's own decisions: [docs/decisions.md](../docs/decisions.md).

1. **Root files stay uppercase** (2026-11-24): agents and GitHub look for exact names like `AGENTS.md`, and Linux is case-sensitive, so `agents.md` goes unread there; the rest stays lowercase kebab-case ([standards 24](../docs/standards.md)).
2. **Six SDLC stages, not eight DevSecOps ones** (2026-11-24): one model is simpler and has a gate per stage; Code joins Build, CI scans join Test, Release joins Deploy, Operate and Monitor become Maintain; control numbers unchanged ([guide 06](06-secure-agentic-sdlc.md)).
3. **The template's backlog is GitHub issues** (2026-11-24): issues aren't copied into new projects, cost no context and keep their history.
4. **GitHub issues replace `TODO.md` in projects too** (2026-11-24): parallel branches no longer conflict on one file, cloud agents and factories start from issues, a PR closes its issue, and closed ones keep their history; the agent takes the oldest open issue ([AGENTS.md](../AGENTS.md) rule 8).
5. **GitHub-facing pages get a front-page header; agent-read docs stay plain** (2026-11-24): people read `README.md`, `CONTRIBUTING.md` and `SECURITY.md` on GitHub, so they open with a centred title and a bold tagline and look finished; `AGENTS.md`, `docs/` and the guides cost context every read, so they start with a plain title and one line. Both keep a compact body of bold-labelled numbered points.
6. **`intent.md` replaces the project brief** (2026-11-24): Anthropic's AI-native SDLC starts from an intent with six headings (Problem, Proposed outcome, Affected users and systems, Constraints, Success criteria, Open questions); `docs/intent.md` holds the project's, and the issue form gives each change the same headings ([guide 02](02-the-files.md) section 5.3).
7. **Step-by-step procedures are skills, not docs** (2026-11-24): kickoff, the PR steps and deploy moved from `docs/` to `.claude/skills/`, as Claude Code and the course do: a skill loads only when used, so `docs/` holds what the project is and costs less to read; every coding agent reads the `SKILL.md` format, and AGENTS.md links each one. The `pull-request` skill keeps only its two steps said nowhere else.
8. **`code-standards.md` is `standards.md`, with its modules marked** (2026-11-24): the course's name, shorter, cited as "standards 24"; the Terraform, containers, AI, web UI and browser-test sections say which module they belong to, so a project skips what it doesn't use, and no rule number changed.
9. **`known-mistakes.md` is `lessons.md`** (2026-11-24): "lessons learned" is the standard term, short and positive, and each entry is a mistake with its fix; cited as "lessons 9", with AWS's in `docs/aws/lessons.md` and no number changed.
10. **Improving is a step before every merge** (2026-11-24): the `pull-request` skill's step 2, as the course's improve loop: look at what went wrong, make a mistake made twice into a check or else a lesson, and drop stale lessons; before, rule 18 said only "in the next PR", with no set moment.
11. **Core docs flat; each module's docs in its own folder** (2026-11-24): the core sits in `docs/` itself, so agents find what they read every session at the top; `docs/aws/` and `docs/web/` hold each module's docs, so a project without one deletes its folder at kickoff, and `templates/` holds files to copy. CI's word limit checks every folder.
12. **Plans are deleted once built; the issue and PR are the record** (2026-11-24): a `docs/changes/<branch>/` folder per change was the other option, but it grows with every change and an agent would read stale plans as current. The issue keeps the intent, the PR keeps what was built and why, and git keeps the deleted plan, so `git log --all -- docs/plan-*.md` finds any old one ([AGENTS.md](../AGENTS.md) rule 13).
13. **The `.env` deny rules and the push rule stay in `.claude/settings.json`** (2026-11-24): moving them into the guard hook would have made `Profile` the one switch, so kickoff edits no settings, but a settings rule holds even when a hook fails or bash is missing, and a hook fails open. A prototype still drops them at kickoff (the `kickoff` skill 7); the guard adds what settings rules can't see, such as a shell command naming `.env`.
